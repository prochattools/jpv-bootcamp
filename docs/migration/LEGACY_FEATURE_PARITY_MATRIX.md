## Current acceptance blockers

1. the current live real-source plan has 14 unresolved relationships: 6 `bunny_target_schema_guid_first_compatibility_required`, 7 `lesson_comment_schema_registration_required`, and 1 `space_media_schema_registration_required` for the source-proven community `space_og_image` → future `payload_spaces.ogImage` relationship;
2. the two source `space_cover_photo` records are no longer schema decisions: both belong to migrated course spaces and now target existing `payload_courses.coverImage`; they remain blocked only on binary media import execution;
3. forward schema remains intentionally unregistered behind migration29: undated Forward A = Bunny GUID-first plus `lesson_id` normalization/FK, Forward B = physical `payload_lesson_comments`, Forward C = `payload_spaces.ogImage`;
4. lesson-comment reactions remain source-evidence gated because the current application has no reusable generalized reaction runtime; add a lesson reaction target only if actual JPV source proves lesson-specific reactions need parity;
5. idempotent binary media import execution tooling is not yet complete for media that already has target semantics;
6. staging-write readiness remains blocked until migration29 ordering is resolved, the prepared forward schema is authorized/registered, binary imports are executable, and a separately authorized staging-write packet is approved.
